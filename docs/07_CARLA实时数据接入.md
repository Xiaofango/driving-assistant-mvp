# CARLA 实时数据接入

日期：2026-10-28。

## 运行

在项目目录运行 `scripts/start_demo.ps1`。已有 CARLA 服务时，可以直接运行 `.venv\Scripts\python.exe -m da_mvp.web_demo --mode carla`。默认数据源为 CARLA；内存模式需要显式指定 `--mode memory`。

CARLA 是仿真数据源。页面摄像头与车辆读数来自当前仿真；本系统没有连接真实道路车辆。

## 数据如何进入 DA

后台采集器持续接收新的 CARLA 世界帧，保存同一帧的车辆位置、速度、加速度和周边车辆观测。读取 API 时只计算缓存年龄，不重新盖采集时间戳。摄像头回调单独保存图像帧号、仿真时间和接收时间；画面停帧与数值延迟分别判断。

网页每轮先获取一份输入快照，把它直接传入 `DrivingAssistant.handle(..., snapshot=...)`；交互记录的 `agent_input` 保存这份快照，`response.action_detail.observation` 保存来源、采集时间、世界帧号和仿真时间。前后状态变化不再被冒充为同一帧中的物理执行结果。

外部测试程序或上层 PC 可读取 `GET http://127.0.0.1:8765/api/agent-input`，返回 `schema_version: "1.0"` 和当前 `snapshot`。这是本机只读数据接口，尚未实现 MQTT 或 PC 多智能体运行时集成。

## 持续输入面板与缓存

采集线程每接收到一个新的世界帧样本，就将当时的完整结构化输入复制进场景内的环形缓存，无需用户发话，也不依赖浏览器是否打开。缓存最多 300 条，不含 JPEG；过量时淘汰最旧记录。重复／倒退帧不会增加计数。`samples_total` 是本场景累计接受的样本数，不是 CARLA 总帧数。

`GET /api/telemetry-stream` 返回累计采样数、缓存条数、淘汰条数、最近最多 30 条输入和当前健康快照。`sample_rate_hz` 根据最近最多 30 个样本的单调接收时间计算；它描述最近接受区间的历史接收频率，当前是否在线仍由 `snapshot.telemetry.status/age_ms` 判断。

页面入口“CARLA → DA 持续输入”可打开采集明细、最新输入 JSON。`GET /api/telemetry-export.jsonl` 将最近最多 300 条记录作为 JSONL 附件下载，每行一个输入快照。未采集到数据或处于内存模式时不提供伪造下载。重置演示清空本场景缓存和累计计数。

## 新增字段

| 字段 | 来源与含义 |
| --- | --- |
| `telemetry` | 世界帧、仿真时间、采集年龄、连接状态和采集错误 |
| `camera` | 图像帧、图像仿真时间、图像年龄、图像是否就绪或过期 |
| `vehicle` | 自车位置、朝向、加速度、道路/车道标识、路口状态与最近控制量 |
| `environment.traffic_light` | 当前是否受交通灯影响及灯色；无生效灯不显示为绿灯 |
| `environment.front_vehicle` | 搜索范围内同道路、同车道、同方向前车及几何估算车身间距；无符合条件观测时为 null |
| `environment.motion` | 车辆运动状态、持续静止时间；静止不自动等同于卡住 |
| `events` | 碰撞/压线传感器事件与操作台事件，分别标注来源 |

自车/周边位置是 CARLA 仿真真值输入，未运行视觉感知模型。交通灯、限速和控制量来自 CARLA API 的最近 tick，不应理解为所有字段都由同一传感器采集。TM 启用状态、跟车等级是本程序向 TM 提交的配置；导航 ETA 仍是几何演示估计。

## 能问什么

- “为什么停了”：结合运动、交通灯和前车观测给出说明；证据不足保留未知。
- “前车离我多远”：回答当前仿真帧的车身间距估算，不修改跟车参数。
- “当前道路和车道”：回答地图 road/lane 标识和当前位置。
- “最近发生了什么”：报告最近事件并区分传感器与人工模拟来源。
- “不要把跟车距离调远”：保留状态，无写调用。

## 异常与权限

CARLA 数值输入未就绪、过期或断连时，DA 不使用旧值生成当前事实或执行参数请求。摄像头过期时不继续返回旧 JPEG 充当实时画面；新鲜数值查询不因独立的画面延迟被阻断。未知道路限速显示未知，不补成固定 30 km/h。

碰撞/压线是传感器观测，不自动等于量产 ADAS 接管请求。人工注入接管告警仍属于演示操作台，来源明确保留。实际驾驶由 CARLA TM 控制。

## 验证

单元测试覆盖状态过期、否定指令、查询无写入、事件来源和实际输入快照一致性。CARLA 现场验证应检查世界帧和图像帧持续前进、位置/速度值来自当前自车、查询回复引用采集帧，并验证断连/停帧时不继续报告 live。现场验收记录另存于 `.build/live_data_20261028/`。

2026-10-28 已执行：

- 44 项回归测试通过。网页 API 测试使用测试替身；以下采样另用真实 CARLA 0.9.16 运行实例。
- 最终场景连续 10 次现场采样，世界帧从 59664 前进到 59898，摄像头帧从 59666 前进到 59896；自车读数从停车逐步升至约 26.6 km/h。世界与摄像头各自保留帧号，未伪装成完全同步的同一帧。
- 五类只读查询的 `observation.frame` 均等于该轮保存的 `agent_input.telemetry.frame`，没有网关写调用。
- 临时生成前车进行验证：输入识别到测试车 ID 31，车身间距约 9.4 米、前车速度约 0.1 km/h，源为 `carla_actor_map_ground_truth`。测试后销毁该车，记录见 `gap-probe.json`。
- 现场接收到了 `carla_sensor` 来源的压线与车辆接触事件，来源与帧号均进入页面事件记录。这不代表 ADAS 接管告警；没有把它们映射成虚构接管事件。
- 页面检查覆盖 1600×900、1366×768、390×844，未发现横向溢出或浏览器脚本错误。断连提示以浏览器注入异常响应验证；数值/相机过期和拒止规则由测试快照及纯函数回归覆盖，没有为此强制关闭 CARLA 服务器。
- 重置演示改为复用现有 CARLA/TM 连接及传感器，在空闲出生点复位车辆。现场连续两次重置后，自车 ID 保持 39，世界帧和摄像头恢复前进，历史清空；记录见 `reset-probe.json`。复位前已清理本次验收早先进程遗留的对象。

本次验收证明当前数据接入、查询和展示链路，不证明路线节时、自动超车或自动泊车等执行能力。
