# 子 Agent 演示脚本(09)

给"我们能做出用于驾驶的子 Agent"这个命题设计的演示动线。总时长 8~10 分钟。

## 演示主线:三件事

观众看完只需记住三件事,所有环节都为它们服务:

1. **可信的感知**:回答全部对齐真实仿真帧,数据过期它自己会说,不编。
2. **受约束的执行**:能做的(设置/环境/场景/录制)都有网关回执;不能做的(变道/直接控车)明确拒止。
3. **可被集成**:每轮留痕可审计,`/api/agent-input` 暴露带版本号的标准输入——这是"子 Agent"而不是"玩具"的证明。

反面教材:按面板顺序把按钮点一遍。那是在演示遥控器,不是 Agent。

## 动线(按时间)

### 第 0 分钟|开场定调

- 点**重置演示**,等状态徽标变"数据与画面实时同步"、帧号持续跳动。
- 开场词:"这是一个座舱驾驶助手子 Agent 的仿真原型。它持续感知车辆与环境,理解自然语言,在安全规则内执行,并且每一步留下依据。接下来 8 分钟,各位可以随时打断提问。"
- **让观众看**:顶部连接徽标、FRAME 计数、车速。一句话点破:"页面上所有数字都来自当前仿真帧,不是录制的。"

### 第 1~2 分钟|感知层:它长着眼睛

- 打开 **"CARLA → DA 持续输入"** 弹窗:累计采样、实际频率、最近采样表。
- 说:"采集在服务端持续进行,关掉页面也不会停;数据延迟或断连时它会如实标注,不会拿旧数据冒充实时。"
- 导出一次 JSONL(可选,工程师观众会感兴趣):"上层系统拿到的是同一份输入。"
- **证明**:感知是持续的、有新鲜度语义的、可导出的。

### 第 2~3 分钟|理解层:它真的在看世界

依次说(每次停 1~2 秒让观众读回复里的"依据 F 帧号"):

- "为什么停了"
- "前车离我多远"
- "当前道路和车道"
- "我现在开多快"

点题:"注意每条回复都挂着依据帧号和判断理由;前车间距明确标注是几何估算、不是视觉识别——它不夸大自己的能力。"
- **证明**:回答基于当前帧计算,可追溯,诚实标注方法。

### 第 3~4 分钟|安全边界:它知道自己的禁区

- "帮我超车" → 无条件拒止 + 理由;"帮我变道"(不带方向)→ **追问方向**,不猜测执行。
- 点**注入模拟接管告警**,再随便问一句普通问题 → 告警优先,请求暂不执行。
- 说:"危险动作不在工具白名单;紧急告警优先于一切;参数不全它追问而不是猜。这三条是硬规则,不是提示词。"
- **证明**:安全约束是代码级的(见 `safety.py`),子 Agent 的分工边界清晰。

### 第 4~5 分钟|受控执行与分层驾驶指令:能做的都有回执

- **"开到 40"** → TM 目标车速生效,状态区显示"目标车速 40 km/h";**"向左变道"** → 车道号真实变化(看"道路/车道"一栏);**"踩油门"** → 被拒:"TM 驾驶中,直接控制被分层权限拒绝";**"暂停自动驾驶"→"踩油门"** → 车真的动了 → **"恢复自动驾驶"**。
- 说:"第一层意图由 TM 执行;第二层直接控制只在 TM 暂停后开放。指令能到车,但永远分层、有门、有回执。"
- "跟车距离调远一点" → 交互记录里展开"数据依据与执行回执":原等级、目标等级、网关回执、实测间距与设置值分开显示。
- "换一条更快的路" → 回复明确"只确认路径提交,轨迹未验证"。
- 说:"每个写操作都要拿到网关回执才算成功;没有确认,它就说没有确认。"
- **证明**:执行链路完整、失败语义诚实。

### 第 5~6 分钟|环境感知(打开"环境/感知/场景注入"面板)

- "现在天气怎么样" → 报真实天气参数(雨量/雾/湿度/太阳高度角)。
- **"下雨"**(全场最直观的一刻):摄像头画面真实下雨,再问一次天气 → 雨量读数变为 60%。
- "附近有行人吗" → 地图真值 + 语义分割双来源,来源分开表述。
- "最近障碍物多远" → 激光雷达/毫米波/深度/障碍物传感器多源合并,stale 的标注"未计入结论"。
- "我们现在在哪" → GNSS + 道路信息。
- 说:"数据维度决定 Agent 能力维度。接入的每一类传感器,都直接变成它能回答的新问题。"
- **证明**:多传感器融合 + 来源透明。

### 第 6~8 分钟|压轴:同一句话,两个答案

这是全场的记忆点,一定留足时间:

1. 先问一次 **"为什么停了"** → 当前答案(例如"证据不足,不能确认原因")。
2. **"前面放一辆事故车"** → 注入成功回执。
3. 等车流受影响、本车停下后,再问一次 **"为什么停了"** → 这次回答引用同车道前车证据(blocked_by_vehicle)。
4. 点题:"同一句话,不同时刻,不同答案,因为它是基于实时状态回答的——这就是 Agent 和放录音的区别。"
5. "清除场景" → 交通恢复。
6. (可选)"模拟行人横穿马路" → 问"附近有行人吗",行人在 20~30 米处被检出。
7. "开始录制"…"停止录制" → 工程完整性:旅程可回放,文件在 `tmp/recordings/`。
- **证明**:闭环感知-决策,场景注入是它的"测试用例生成器"。

### 第 8~10 分钟|收尾:可被集成的证据

- 滚动**交互记录**:"每一轮都保留原话、意图、判断依据、网关回执、前后状态对比——可审计。"
- 打开 `http://127.0.0.1:8765/api/agent-input`(或口头说明):"带版本号的标准输入接口,schema 1.1,上层 PC 或编排系统可以直接组合它。这才是'子 Agent'的交付形态。"
- 收尾词:"感知可信、执行受约束、行为可审计、接口可组合——这四条就是我们能做出驾驶子 Agent 的证据。"

## 给不同观众的重心调整

| 观众 | 压缩 | 加强 |
| --- | --- | --- |
| 领导/客户 | 交互记录明细、导出 JSONL | 天气下雨的画面冲击、"同一句话两个答案"、拒止故事 |
| 工程师 | 开场白 | `/api/agent-input`、采样流导出、同步模式(Q&A 备用:20 Hz 定步长,用于确定性复现) |
| 安全/评审 | 天气细节 | 拒止、告警优先、stale 数据不采信、失败回执留痕 |

## 演示前检查单

1. 提前 10 分钟:确认 CARLA 与页面服务已在跑(帧号在跳);执行一次完整走场。
2. 点重置后**等 5~10 秒**再开口第一句话(等 live 数据和 TM 起步)。
3. "事故车"注入偶发失败的预案:如实展示失败回执本身就是演示点("失败也留痕,不会假装成功"),然后清除场景重试一次。
4. 演示中**不要切同步模式**(属基础设施,观众易冷场),留给工程师 Q&A。
5. 若换机器演示:先跑 `scripts\start_demo.ps1`;若曾强杀过进程,先清理残留(见 docs/08 第 10 节验收要点与本机排查备忘)。

## 一页话术清单(照读顺序)

为什么停了 → 前车离我多远 → 帮我超车(拒止)→ 帮我变道(追问方向)→ 开到 40 → 向左变道 → 踩油门(分层拒止)→ 暂停自动驾驶 → 踩油门(直接控制)→ 恢复自动驾驶 → 注入接管告警 + 任意提问(优先级)→ 跟车距离调远一点 → 换一条更快的路 → 现在天气怎么样 → 下雨 → 再问天气 → 附近有行人吗 → 最近障碍物多远 → 我们现在在哪 → **为什么停了(第一次)** → 前面放一辆事故车 → **为什么停了(第二次,答案不同)** → 清除场景 → 模拟行人横穿马路 → 附近有行人吗 → 开始录制 → 停止录制
